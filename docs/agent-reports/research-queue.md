# Crowd research queue: many volunteers, their own AI, verified quotes

Built 2026-10-04. Volunteers each use their **own** model access (OpenAI or Anthropic Claude) to research rare diseases the atlas doesn't map in depth yet, in parallel and without cloning the repo. The server assembles every task, fetches the literature itself and verifies every quote. Pages: `/research-queue` (overview, live stats, next 20, leaderboard, worker setup) and `/research-queue/run` (the browser runner). Disease pages `/d/<id>` show a "Community research" block when a disease has accepted claims.

## Architecture

| Piece | Path |
|---|---|
| Seed list (7,750 diseases, priority order) | `pipeline/crowd/build_queue.py` → `web/app/api/queue/_data/seed.json` (1.5 MB, bundled into the route) |
| Queue, leases, packets, PubMed, verification, stats | `web/lib/server/queue.ts` |
| API | `web/app/api/queue/{claim,task,submit,done,stats,token,me,sweep}/route.ts`, `disease/[id]/route.ts` |
| Pages and components | `web/app/research-queue/**`, `web/components/queue/**` (`QueueHome`, `QueueRunner`, `CommunityResearch`, `queue-client.ts`) |
| `/d/` hook | `components/global/GlobalDiseaseView.tsx`: one import plus `<CommunityResearch id={row.id} />` after the DisMech block. It renders nothing when there are no claims. |
| Standalone worker | `web/public/worker/rare-atlas-worker.mjs`, generated by `pipeline/crowd/build_worker.mjs` from `integrations/openai/siwc.mjs` + `llm.mjs` (inlined) + `pipeline/crowd/worker_main.mjs` |
| Export to the graph | `pipeline/crowd/export.mjs` → `data/curated/crowd.json` |
| End-to-end test | `pipeline/crowd/test_queue.mjs` |

**Storage.** The queue uses the same backend choice as `store.ts` (`storeMode()`):
- On Vercel it uses Upstash Redis over REST, with the same `KV_REST_API_URL`/`KV_REST_API_TOKEN` or `UPSTASH_REDIS_REST_*` variables. Its own small REST client adds sorted sets, lists and hashes.
- Locally it uses the JSON file `web/.data/queue.json`, guarded by a cross-process lock file (`queue.json.lock`, O_EXCL). This is a separate file from `store.json`, so the two adapters never overwrite each other.
- All keys are prefixed `rq:`.

**Seed priority** (`build_queue.py`, weights recorded in the seed's `meta`):
- Who is included: monogenic index rows (1–5 genes, OMIM or Orphanet gene source) that are not one of the 45 deep diseases and share none of their genes. Non-disease rows (blood groups, susceptibility, QTL and so on) are dropped.
- Score:
  - +3 trials matched by name (+1 if matched by gene only);
  - +2 patient organisations, +1 registry;
  - +2 Orphanet prevalence;
  - +1.5 **no** DisMech chain (the mechanism gap is biggest there);
  - +3 mechanism neighbour of a deep disease (+1 same cluster);
  - up to +1 for HPO depth.
- Top of the list: macrocephaly-autism syndrome (PTEN), MEN2B (RET), MPS IIIA/B/C, Lhermitte-Duclos, Blau, Farber, Phelan-McDermid, Rett.

## Queue semantics

- **Available list:** sorted set `rq:avail`. Untouched diseases carry their seed rank (0…N-1). A disease that comes back incomplete carries `-1e13 + now`, so it sits **ahead of every untouched disease**, oldest first.
- **Claim** (`POST /api/queue/claim`), atomic without Lua:
  1. `ZPOPMIN rq:avail`. Redis pops each member exactly once, so concurrent volunteers always get different diseases.
  2. `SET rq:lease:<id> … NX EX` as a second guard.
  3. The lease is recorded in `rq:leases` (score = expiry) and `rq:ulease:<uid>`.
  - If PubMed fails, the disease goes back at its original score.
  - One lease per volunteer. Claiming again returns the same packet ("resume").
- **Lease:** 7 hours. The lease record outlives the lease by 2 days (grace), so the sweeper still knows who held it.
- **Submissions** (`POST /api/queue/submit`) are verified and stored immediately. The checklist is recomputed and returned, so the UI ticks.
- **End of lease**, by "I'm done" (`POST /api/queue/done`) or by expiry:
  - The server guards with `ZREM rq:leases id` (exactly one finaliser wins), recomputes coverage from all accepted claims and records the round in the disease's history.
  - **Complete:** the disease goes to `rq:done` and leaves the queue.
  - **Incomplete:** it goes back to the top with its gaps listed. The next packet says what's missing, focuses the PubMed query on those topics, excludes the PMIDs already used and shows the earlier rounds.
  - **Retired:** after `MAX_ROUNDS` (3) worked rounds (a round with ≥1 submission), an incomplete disease moves to `rq:retired` with its gaps. Without this cap, diseases with no therapy literature would sit at the top forever and starve the rest of the queue. Abandoned leases (0 submissions) don't count as rounds.
- **Expiry is lazy:** every claim first finalises up to 10 expired leases. `GET|POST /api/queue/sweep` (Bearer `CRON_SECRET`) does up to 200; `?reconcile=1` also re-adds any disease that fell out of every list (e.g. a crash between ZPOPMIN and the lease write; the lease-NX guard keeps this safe).
- **Checklist** (`CHECKLIST` in queue.ts):

  | Item | Done when |
  |---|---|
  | Mechanism | ≥2 distinct verified quotes on `driven_by`/`has_effect` with a class of loss of function, haploinsufficiency, dominant-negative or gain of function |
  | Biological process | ≥1 (`participates_in`/`disrupts`) |
  | Therapies | ≥1 with a stage (`developed_for` + `therapy_stage`: approved, clinical, preclinical or tried off-label) |
  | Phenotypes | ≥3 distinct (`has_phenotype`) |
  | Natural history | ≥1 (`natural_history`) |
  | Research groups | ≥2 distinct senior authors |

## Task packet

`claim` and `GET /api/queue/task` return one packet:

- `lease`: `diseaseId`, `token`, `expiresAt`, `round`, `maxRounds`.
- `disease`: name, synonyms, genes, MONDO, OMIM and ORPHA ids.
- `known`: curated mechanism classes, DisMech yes/no, mechanism cluster, trial/organisation/registry counts, prevalence, mechanism-neighbour-of.
- `checklist`, `missing`, `previousRounds`.
- `abstracts` (≤15): `pmid`, `title`, `abstract`, `year`, `journal`, `senior_authors` (the last two authors with their first affiliation, emails stripped).
- `instructions` (the extraction prompt), `schema` (strict JSON Schema), `batchSize` (5), `statusLabel`.

PubMed is queried server-side through NCBI E-utilities:
- `tool=rare-disease-atlas`, no email parameter, optional `NCBI_API_KEY`.
- Requests are throttled to ≥350 ms apart per instance and ≤3 per second across instances, through a store counter. 429 and 5xx responses are retried.
- Queries run in order and fill up to 15 abstracts:
  1. disease names/synonyms AND the missing topics;
  2. the names alone;
  3. the gene in a germline or syndromic context AND the topics.
- Records are cached in `rq:pm:<pmid>` and searches in `rq:pmq:<hash>` (7 days).

Claim schema (per claim, all fields required, `additionalProperties: false`):
- `subject`, `relation` (`causes`, `driven_by`, `has_effect`, `participates_in`, `disrupts`, `developed_for`, `targets`, `has_phenotype`, `natural_history`), `object`;
- `mechanism_class` (or null), `therapy_stage` (or null);
- `quote` (ONE verbatim sentence), `pmid`, `study_type`, `species`, `certainty`, `negated`.

The top level also has `research_groups[]`, each `{pmid, senior_author, affiliation}`.

## Security: the server never trusts the client

- **Accounts:** an atlas account is required. A browser call uses the existing `atlas_session` cookie from `lib/server/community.ts`, with same-origin checks on POSTs. The worker uses a **worker token** (`rqw_…`): created on `/research-queue` while signed in, shown once, stored only as a SHA-256 hash, valid for 30 days and revocable. A deleted account's tokens stop working.
- **Anonymous use is refused (401).** Rate limits: 20 claims and 120 submissions per volunteer per hour, plus per-IP limits.
- **Every claim is checked** for:
  - the exact schema: no extra fields, enums, length limits, and a class or stage where the relation needs one;
  - a **PMID that is in this lease's packet**;
  - a quote of at least 25 characters and 4 words that is a **verbatim substring of that PMID's title or abstract as the server fetched it**, after NFKC, dash, curly-quote and whitespace normalisation (the same `norm()` as `pipeline/openai/common.mjs`);
  - a quote that spans **one sentence** only;
  - a valid, unexpired lease token held by the caller.
- **Research groups** must name one of that PMID's last two authors exactly, with an affiliation copied from that author's PubMed affiliation. Emails, links and phone numbers are rejected.
- **Duplicates** (same PMID, quote, relation, object and negation) are not credited. Accepted, rejected and duplicate counts are kept per volunteer and **per provider**.
- **Storage:** accepted items are stored with `status: "community-researched, AI-extracted, quote-verified, unreviewed"`, the volunteer's handle (auto `volunteer-xxxxxx`, changeable) and the provider and model they report. Leaderboards show handles only.
- **API keys never reach the atlas.** The BYOK runner keeps the key in memory (sessionStorage only if "remember for this tab" is ticked) and calls the provider directly. ChatGPT tokens stay on the volunteer's machine (`~/.rare-atlas-worker/secrets`, mode 600).
- **Known limit:** verification proves the sentence exists in the abstract, not that the model read it correctly. Claims stay "unreviewed".

## Three (plus one) ways to take part

1. **Browser runner, bring your own key** (`/research-queue/run`).
   - Choose **OpenAI** or **Anthropic (Claude)**:
     - OpenAI: `POST https://api.openai.com/v1/responses` with structured outputs (`text.format.type = json_schema`, strict). Default model `gpt-6.1-sol`; "List my models" reads the key's catalogue.
     - Anthropic: `POST https://api.anthropic.com/v1/messages` with `x-api-key`, `anthropic-version: 2023-06-01` and `anthropic-dangerous-direct-browser-access: true`, with strict JSON through a forced tool call (`tool_choice: submit_claims`, `input_schema` = the claim schema). Default `claude-sonnet-5-5`; `claude-opus-5-5` is selectable.
   - **CORS was verified on 2026-10-04:** both APIs answer the browser preflight with `Access-Control-Allow-Origin: *` and allow the needed headers. If a network or extension blocks it, the runner says so and points to the worker.
   - Cost: the runner shows the estimated tokens and cost per task (about 3 calls, roughly 15k input and 5k output tokens) from editable per-million prices, then the actual spend from the provider's usage figures.
2. **Local worker with a ChatGPT Plus/Pro plan** (or an API key):

   ```bash
   curl -fsSLO https://rare-disease-atlas-five.vercel.app/worker/rare-atlas-worker.mjs
   node rare-atlas-worker.mjs --server https://rare-disease-atlas-five.vercel.app
   ```

   - The worker is one file of about 2,100 lines with no dependencies; it needs Node 20 or newer.
   - On first run it asks for the worker token (or reads `RARE_ATLAS_TOKEN`), then signs in with ChatGPT through the 127.0.0.1 loopback flow on the volunteer's own machine.
   - It then loops: claim, run batches of 5 abstracts, submit, hand back.
   - Flags:
     - `--api-key` uses `OPENAI_API_KEY`;
     - `--provider anthropic` uses `ANTHROPIC_API_KEY` (default `claude-sonnet-5-5`, `--model claude-opus-5-5`);
     - `--model`, `--max-tasks N`, and `--max-calls N` (a cost cap);
     - the subcommands `login`, `status` and `logout`.
   - Ctrl-C once hands the disease back with what was found; twice exits.
   - After changing `integrations/openai/*.mjs` or `worker_main.mjs`, rebuild it with `node pipeline/crowd/build_worker.mjs`.
3. **Account:** required for both, so contributions carry a handle and can be rate-limited.
4. **Any agent, including Claude Code** (below).

## Run it with Claude Code (or any agent)

A volunteer with Claude Code can say *"download and run the Rare Disease Atlas worker with `--provider anthropic`"*, or *"research one task from the Rare Disease Atlas queue"*. For the second, the agent itself reads the abstracts and makes **two API calls** with a worker token (create one on `/research-queue`):

```bash
# 1. Claim (or resume) a disease: returns the task packet
curl -s -X POST "$SERVER/api/queue/claim" -H "Authorization: Bearer $RARE_ATLAS_TOKEN" -H "Content-Type: application/json" -d '{}'
#    -> {"packet": {"lease": {"token": "...", ...}, "disease": {...}, "checklist": [...], "abstracts": [...],
#                   "instructions": "...", "schema": {...}}}   or {"empty": true}

# 2. Submit claims (repeatable during the 7-hour lease); each one is verified, the response lists rejections and the checklist
curl -s -X POST "$SERVER/api/queue/submit" -H "Authorization: Bearer $RARE_ATLAS_TOKEN" -H "Content-Type: application/json" -d '{
  "token": "<packet.lease.token>", "provider": "anthropic", "model": "claude-sonnet-5-5",
  "claims": [{"subject": "...", "relation": "driven_by", "object": "...", "mechanism_class": "loss_of_function",
              "therapy_stage": null, "quote": "<one sentence copied exactly from packet.abstracts[i]>", "pmid": "<that PMID>",
              "study_type": "functional_study", "species": "mouse", "certainty": "suggested", "negated": false}],
  "research_groups": [{"pmid": "...", "senior_author": "<exactly as in senior_authors>", "affiliation": "<copied from it>"}]}'
```

Then hand the disease back with `POST /api/queue/done` and the body `{"token": "<packet.lease.token>"}`; otherwise the lease simply expires. `packet.instructions` and `packet.schema` are the full rules. `GET /api/queue/task` returns the packet you hold. `GET /api/queue/stats` and `GET /api/queue/disease/<MONDO id>` are public.

## Export to the graph

```bash
node pipeline/crowd/export.mjs            # production queue: KV_REST_API_URL/TOKEN from web/.env.local; read-only
node pipeline/crowd/export.mjs --file     # local web/.data/queue.json
python3 pipeline/build_graph.py           # merges data/curated/crowd.json like any fragment
```

**What gets exported:**
- Single-gene diseases become `disease:<GENE>` umbrella nodes with `attrs.layer: "crowd"` and subtypes, plus the gene node.
- Claims map to edges:
  - `causes`;
  - `driven_by` to `mech:loss-of-function` and the other three classes;
  - `has_phenotype`, only for an exact HPO label;
  - `developed_for` from new `therapy:` nodes;
  - research groups become `researcher:` nodes with `works_on` edges, where the evidence quote is the verbatim paper title.
- Every edge is `status: "unverified"` with confidence ≤ 0.5 (0.3 plus 0.1 per extra PMID). The evidence carries `extracted_by: "openai:<model> (community)"` or `"anthropic:<model> (community)"`, `verified: true`, and the handle and round.
- Negated claims become counter-evidence, or are skipped if they are the only evidence.
- `participates_in`, `disrupts`, `targets` and `natural_history` stay on the `/d/` page; there is no safe node mapping for them yet.

**Safety checks:** the script refuses any Redis command other than SMEMBERS, LRANGE and GET, and refuses to write if any edge would dangle or lack a quote or URL. `--min-claims N` filters thin diseases.

**Caution:** merged crowd diseases become `disease:` nodes, so parts of the UI that count or route "mapped" diseases will treat them as mapped. Review `crowd.json` before you run `build_graph.py` for a release.

## Environment variables

| Variable | Where | Needed |
|---|---|---|
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` (or `UPSTASH_REDIS_REST_*`) | Vercel | Yes; already set for community accounts. Without them the queue answers 503 "opens soon". |
| `SESSION_SECRET` | Vercel | Yes; already required by accounts |
| `CRON_SECRET` (≥16 characters) | Vercel | Optional: protects `/api/queue/sweep`. Expiry also runs lazily on every claim. |
| `NCBI_API_KEY` | Vercel | Optional: 10 requests/s instead of 3 |
| `QUEUE_MAX_ROUNDS` | Vercel | Optional, default 3 |
| `RARE_ATLAS_TOKEN`, `RARE_ATLAS_HOME`, `RARE_ATLAS_SECRETS_DIR`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` | Volunteer's machine (worker) | As needed |

For an hourly sweep, add `"crons": [{"path": "/api/queue/sweep", "schedule": "0 * * * *"}]` to the Vercel project config (Hobby plans allow daily only). Vercel sends `Authorization: Bearer $CRON_SECRET` itself.

## Test results (2026-10-04, local dev server, FILE store only)

`node pipeline/crowd/test_queue.mjs` passed **38/38** checks with a fake extractor that copies real sentences from the packet. No model calls were made. The checks:

- **Access:** an anonymous claim gets 401.
- **Concurrency:** two volunteers claiming at the same moment got **different diseases** (MONDO:0011537 and MONDO:0008082), each with 15 PubMed abstracts and a 7-hour lease. Claiming again resumes the same lease.
- **Verification:** verbatim claims and a valid research group were accepted. The following were **rejected**: a forged quote (one word altered: "not a verbatim sentence of PMID 34161704"), a PMID outside the packet, a two-sentence quote, an unknown relation, an extra field, `driven_by` without a class, and an invented senior author. A resubmitted claim counts as a duplicate, not as credit. Another volunteer cannot submit to someone else's lease (409).
- **Checklist:** mechanism ticks to 2/2 after two verbatim quotes.
- **Expiry:** after the lease expired, a late submit got 410. The **next claim (another volunteer) received that same disease first** as round 2. Its packet listed the gaps (process, therapies, phenotypes, natural history, research groups) and the earlier expired round, and it carried 15 *new* abstracts.
- **I'm done:** "I'm done" with gaps requeued the disease; stats then showed it first in "next 20", marked as returning with its gaps.
- **Stats:** stats, the per-volunteer counts, the handle-only leaderboard and the public `/api/queue/disease` view (unreviewed label) were all correct.
- **Worker tokens:** a worker token authenticates; an unknown token gets 401; a cross-site POST carrying a session cookie gets 403.
- **Cleanup:** the three throwaway accounts were deleted and the queue file removed.

**Real model run (2 calls of the 3 allowed).** The worker downloaded from `/worker/rare-atlas-worker.mjs` was byte-identical to the built file. It used the existing Sign in with ChatGPT session (`RARE_ATLAS_SECRETS_DIR` pointed at the repo's `.secrets`) and `--max-calls 2`, and returned `gpt-6-astra`:
- Batch 1: 9 claims and 10 groups verified, 0 rejected.
- Batch 2: 3 claims and 4 groups verified, 0 rejected.
- **26 verified, 0 rejected.** The checklist reached mechanism, process, therapies and research groups. The disease went back to the top, still missing phenotypes (2/3) and natural history.

**Other checks:**
- The Anthropic worker path was exercised with an invalid key: the error was handled cleanly and the disease handed back. No real Claude call was made.
- `export.mjs --file` turned the real claims into 14 nodes and 15 edges, all unverified, confidence 0.3–0.4, `extracted_by: "openai:gpt-6-astra (community)"`, with no dangling edges. This was written to scratch, **not** to `data/curated/`.
- The `/d/MONDO:0011537` block and `/research-queue` were rendered and checked in the browser.
- `npx tsc --noEmit` and `eslint` are clean for every new file.
- Afterwards, every test account, `web/.data/queue.json` and `web/.data/store.json` (which my tests had created) were removed. The production Redis was never touched.
